# SOFTWARE REQUIREMENTS SPECIFICATION (SRS)

# MoSJE Centralized De-Addiction & Counselling Management System

---

# 1. INTRODUCTION

## 1.1 Purpose of the Document

This Software Requirements Specification (SRS) document defines the complete functional, technical, operational, architectural, and deployment requirements for the proposed "MoSJE Centralized De-Addiction & Counselling Management System".

The purpose of this system is to digitally transform and centralize rehabilitation, counselling, and beneficiary tracking processes across all de-addiction and rehabilitation facilities supported under the Ministry of Social Justice and Empowerment (MoSJE).

Currently, rehabilitation centers operate independently and maintain records manually or in isolated software systems. This creates multiple operational problems:

* Lack of centralized beneficiary tracking
* No unified national database
* Difficulties in monitoring counselling interventions
* Poor visibility into relapse statistics
* Inability to perform state-wise or center-wise analytics
* Manual reporting burden
* Difficulty in measuring treatment effectiveness
* Inconsistent follow-up monitoring
* Poor coordination between rehabilitation centers
* Lack of real-time data access for government stakeholders

The proposed platform aims to eliminate these inefficiencies through a secure centralized web platform.

---

## 1.2 Problem Statement

Details of counselling and de-addiction interventions provided to beneficiaries at facilities supported by MoSJE are not available on a single platform. This limits the ability to perform patient-wise, center-wise, district-wise, and state-wise analysis of services provided, beneficiaries reached, treatment effectiveness, relapse rates, and rehabilitation outcomes.

As a result:

* Government authorities cannot accurately measure rehabilitation performance.
* Patient history becomes fragmented between centers.
* Referrals are difficult to manage.
* Reporting consumes excessive administrative effort.
* Follow-up tracking becomes inconsistent.
* Relapse monitoring is weak.
* Data-driven decision making becomes difficult.

The proposed system addresses these limitations by introducing a centralized digital ecosystem.

---

# 2. PROJECT OBJECTIVES

The major objectives of the system are:

## 2.1 Centralized Beneficiary Management

To create a unified national platform for maintaining beneficiary records across all MoSJE-supported rehabilitation centers.

## 2.2 Counselling & Rehabilitation Tracking

To digitally record all counselling sessions, treatment plans, relapse incidents, rehabilitation progress, and follow-up activities.

## 2.3 State-Wise and Center-Wise Analytics

To provide real-time dashboards and analytical reports for monitoring:

* Number of active beneficiaries
* Recovery trends
* Relapse statistics
* Center performance
* Counsellor performance
* State-wise intervention effectiveness

## 2.4 Referral Management

To streamline transfer of patients between rehabilitation centers while preserving complete treatment history.

## 2.5 TeleCounselling Enablement

To provide online counselling facilities for remote patients or emergency follow-up sessions.

## 2.6 Government Reporting

To simplify ministry-level reporting through automated PDF and Excel report generation.

---

# 3. SYSTEM OVERVIEW

The system is a web-based centralized rehabilitation management platform developed using Laravel 12 and Blade.

The platform follows a modular architecture where each module is responsible for handling a specific business process.

The application is divided into:

* Authentication Layer
* Role Management Layer
* Patient Management Module
* Counselling Management Module
* Referral Module
* Analytics Module
* Reporting Module
* Notification System
* Audit & Compliance Layer
* TeleCounselling Layer

The system is designed to support multiple rehabilitation centers simultaneously while maintaining secure separation of center-level data.

# 5. SYSTEM ARCHITECTURE

The project follows enterprise-level layered architecture principles.

## 5.1 MVC Architecture

The project follows Laravel's MVC (Model-View-Controller) architecture.

### Models

Responsible for:

* Database interaction
* Relationships
* Query scopes
* Business entities

Examples:

* Patient
* Referral
* CounsellingSession
* Appointment

### Views

Implemented using Blade templates.

Responsible for:

* UI rendering
* Dashboard visualization
* Form handling
* Responsive layouts

### Controllers

Responsible for:

* Request handling
* Validation coordination
* Service layer communication
* Response generation

---

## 5.2 Service Layer Architecture

Business logic is separated from controllers using Service Classes.

Example:

PatientController → PatientService → PatientRepository → Database

Advantages:

* Cleaner architecture
* Easier testing
* Better maintainability
* Reusable business logic

---

## 5.3 Repository Pattern

Repositories abstract complex database queries.

Example repositories:

* DashboardRepository
* PatientRepository
* ReferralRepository

Purpose:

* Avoid query duplication
* Centralize database logic
* Improve scalability

---

## 5.4 Queue Based Processing

Heavy operations will execute asynchronously using Laravel Queues.

Examples:

* Sending SMS reminders
* Report generation
* Dashboard analytics processing
* Email notifications

Benefits:

* Faster UI response time
* Reduced server blocking
* Better scalability

# 6. DETAILED MODULE DESCRIPTIONS

## 6.1 Authentication & Authorization Module

This module controls system access and security.

### Features

* User login
* Password reset
* Session management
* Role assignment
* Permission assignment
* Access restriction
* Route protection
* Login activity logging

### User Flow

1. User enters credentials.
2. Laravel Breeze validates credentials.
3. System checks assigned role.
4. Role-based middleware determines accessible routes.
5. Dashboard is loaded according to role.

### Security Measures

* Password hashing using bcrypt
* CSRF protection
* Session timeout
* Brute force protection
* Rate limiting

---

## 6.2 Patient Management Module

This is the core module of the application.

The module manages the complete lifecycle of a rehabilitation beneficiary.

### Features

#### Patient Registration

The system allows counsellors or clerks to register a new beneficiary.

Captured information includes:

* Full name
* Gender
* Date of birth
* Contact information
* Emergency contact
* Address
* Aadhaar details
* Substance abuse history
* Guardian information
* Initial assessment

#### Patient Profile Dashboard

Each patient has a dedicated dashboard displaying:

* Medical history
* Counselling history
* Relapse history
* Appointments
* Referral history
* Uploaded documents
* Treatment timeline

#### Document Management

The system supports document uploads:

* Aadhaar scans
* Medical reports
* Prescriptions
* Referral letters
* Consent forms

#### Search & Filters

Advanced filters:

* Name
* Phone number
* Patient ID
* Center
* State
* Substance type
* Counsellor
* Registration date

### Workflow

1. Clerk/Counsellor registers patient.
2. Validation rules execute.
3. Patient ID generated.
4. Patient assigned to center.
5. Initial counselling session scheduled.
6. Follow-up process begins.
